1. INTRODUCTION                                       *wiremux-introduction*

Wiremux sends code, prompts, and commands from Neovim to programs in tmux.
Use it with AI assistants, shells, or other tools.

A target is a tmux pane or window that receives text. A definition describes
how to create a target. An instance is a target that already exists.

Compose lets you edit a draft before you choose a target. A draft can contain
several pages. Target metadata lives in tmux and survives Neovim restarts.

Requirements:
  - Neovim 0.11 or later.
  - Neovim running inside tmux.
  - tmux 3.0 or later is recommended.

2. TUTORIAL                                                *wiremux-tutorial*

After the plugin loads, define a terminal:
>lua
  require("wiremux").setup({
    targets = {
      definitions = {
        terminal = { kind = "pane", split = "horizontal" },
      },
    },
  })
<
1. Run `:Wiremux create`.
2. Select `terminal`.
3. Return to Neovim with your tmux navigation keys.
4. Run `:Wiremux send ls -la`.
5. In the target pane, press Enter to run the command.

By default, Wiremux pastes text without Enter and moves focus to the target.
Set `actions.send.submit = true` in your configuration to append Enter.

Merge later examples into your existing configuration. A new `setup()` call
starts from shipped defaults and replaces your previous configuration.

For AI targets and other options, see |wiremux-configuration|.
For Lua mappings, see |wiremux-api|.

3. HOW-TO GUIDES                                              *wiremux-howto*

Compose drafts: |wiremux-howto-compose|
Keys and footer: |wiremux-compose-keymaps| |wiremux-config-compose-footer|
History: |wiremux-compose-history|
Completion: |wiremux-completion|
Motion mapping: |wiremux-howto-send-motion|

Send text and choose prompts ~

Use placeholders to include editor context:
>lua
  require("wiremux").send("Explain {this}")
<
`{this}` contains the source location and any visual selection.
`{file}` contains a path, not file contents. See |wiremux-placeholders|.

Pass a list to choose a prompt:
>lua
  vim.keymap.set({ "n", "x" }, "<leader>ap", function()
    require("wiremux").send({
      {
        label = "Review changes",
        value = "Review the changes in {file}:\n{changes}",
      },
      { label = "Fix diagnostics", value = "Fix {file}\n{diagnostics_all}" },
      { label = "Fix quickfix", value = "Help me fix these:\n{quickfix}" },
    }, { compose = true })
  end, { desc = "Choose a prompt" })
<
The example opens the selected prompt in Compose. Omit `compose` to use your
configured send behavior. See |wiremux.send()| for item fields.

Send keystrokes before or after text ~           *wiremux-howto-pre-post-keys*

Use tmux key names in `pre_keys` and `post_keys`:
>lua
  require("wiremux").send({
    value = "my text",
    pre_keys = { "C-c" },
    post_keys = { "Escape" },
  })
<
For a target with Vim-style editing, use `pre_keys = { "i" }` to enter Insert
mode before the paste. Item fields override the corresponding call options.

Run a tool directly ~                            *wiremux-howto-shell-false*

With `shell = true`, Wiremux creates a shell and types the command into it.
With `shell = false`, Wiremux passes the command directly to tmux:
>lua
  targets = {
    definitions = {
      opencode = { cmd = "opencode", kind = "pane", shell = false },
    },
  },
<
The program then controls the target's lifetime, subject to tmux settings.
The close action can close either kind of target.

Send a motion or selection ~                     *wiremux-howto-send-motion*

`send_motion()` returns `g@`. Use an expression mapping:
>lua
  vim.keymap.set({ "n", "x" }, "ga", function()
    return require("wiremux").send_motion()
  end, { expr = true, desc = "Send motion or selection" })
<
In Normal mode, press `ga`, then a motion or text object such as `ip`.
In Visual mode, select text and press `ga`.

Motion sends keep placeholder-shaped source text literal.

`send_motion()` does not extract blockwise selections correctly.
For blocks, use a Visual mapping that calls
`require("wiremux").send("{selection}")`.

Compose drafts ~                                     *wiremux-howto-compose*

Use `compose = true` to edit text before you choose a target:
>lua
  require("wiremux").send("Review {this}", { compose = true })
  require("wiremux").send("Review {selection}", {
    compose = { title = " Review Selection " },
  })
<
Call `send()` without text to open or resume a draft. Resuming does not add a
page or change the existing draft's configuration.

Unsent drafts last only for the current Neovim session.

Successful confirmation closes and clears the draft before target selection.
Cancelling that picker does not restore the draft.
For recovery, enable |wiremux-compose-history| before confirmation.

Default keys:
  Key              Mode        Action
  <CR>             Normal      Confirm all pages.
  q / <Esc>        Normal      Close according to close_behavior.
  <C-s>            Normal      Hide + append next.
  <C-p> / <C-n>    Normal      Select the previous / next page.
  <C-x>            Normal      Delete the current page.
  K                Normal      Preview the placeholder under the cursor.
  <C-f>            Normal,Insert  Insert a file path.

Insert-mode Enter adds a line. There is no default Insert-mode send binding.
`A` keeps its native append-at-end-of-line behavior.

With one page, `<C-x>` clears its text and keeps Compose open.
With several pages, it deletes the current page and selects the next page.
After the final page, selection wraps to the first page.

`<C-s>` hides the draft and makes the next non-empty Compose input append a
page. It bypasses `on_new_payload` once. Resuming without text does not
consume that instruction. It does not send a message or record history.

Discard has no default key. |wiremux.compose.discard()| removes the current
page. With one page, it discards the draft and closes Compose without asking.
To map discard to `Q`, add this entry under `ui.compose.keymaps`:
>lua
  discard = { "Q", mode = "n", desc = "Discard compose page" },
<
`close_behavior` controls `q` and Escape:
  "ask"      Ask whether to hide, discard, or keep editing.
             This is the default.
  "hide"     Keep the draft and close its window.
  "discard"  Discard every page and close the window.

Closing an empty or whitespace-only draft discards it without asking,
regardless of `close_behavior`.

Set `ui.compose.on_new_payload = "append"` to collect context from several
locations. The other choices are "ask" (default), "keep", and "replace".
The ask dialog initially selects Keep Draft.

Each page keeps its source location, selection, and source line.
Other placeholder values resolve when you confirm the draft.
See |wiremux-placeholders| for timing and resolver rules.

A new non-empty send updates the draft's configuration and delivery options.
This also applies when the input policy keeps the previous pages.

Compose options use this order: item `compose`, call `compose`, then
`actions.send.compose`. The first supplied value wins. Tables do not merge
across these levels. The chosen table overrides `ui.compose` session defaults.

Placeholder preview ~

Place the cursor on a placeholder and press `K`. Press `K` again to enter the
read-only preview. Use `q` or Escape there to close it.

Preview does not change the page. Empty values show `(empty)`.
Unavailable values show a message. `{changes}` uses diff syntax.

Compose footer ~                               *wiremux-config-compose-footer*

`ui.compose.footer` is a boolean, default true. The footer shows only active
Send and Close mappings that Wiremux still owns.

Set `ui.compose.footer = false` to hide it without disabling mappings.
The same field works in action defaults and per-send/item `compose` tables.
Resuming a draft without text keeps its footer setting.

Compose keymaps ~                                  *wiremux-compose-keymaps*

`ui.compose.keymaps` maps action names to one keymap or a list of keymaps:
>lua
  ui = {
    compose = {
      keymaps = {
        send = { "<leader>s", mode = "n", desc = "Send draft" },
        close = {
          { "q", mode = "n" },
          { "<C-c>", mode = { "n", "i" } },
        },
        preview_placeholder = {},
      },
    },
  },
<
Omitted actions inherit their mappings. A supplied action entry replaces all
its inherited mappings, modes, and descriptions. It does not add aliases.

An empty action entry, such as `send = {}`, disables that action's mappings.
An empty outer `keymaps` table does not clear defaults.
`keymaps = false` and `send = false` are invalid.

                               *wiremux-config-compose-use-default-keymaps*
Set `ui.compose.use_default_keymaps = false` to omit shipped main-buffer
bindings. This also removes the `<C-o>` and `<C-i>` jump-list blockers:
>lua
  ui = {
    compose = {
      use_default_keymaps = false,
      keymaps = {},
    },
  },
<
This switch is global-only and defaults to true. Explicitly configured
mappings still apply. Per-send keymaps use the same action replacement rules.

Native mapping replacements, option changes, and deletions survive draft
refresh and reopen. The footer omits keys that Wiremux no longer owns.
Custom callbacks do not get automatic action labels.

For native mappings, see |wiremux-compose-api| and
|wiremux-compose-open-event|.

Compose history ~                                  *wiremux-compose-history*

History keeps confirmed messages for recovery and reuse. It is off by default.
To keep three messages, merge this field into your options:
>lua
  ui = {
    compose = {
      history_limit = 3,
    },
  },
<
Use `:Wiremux history` or |wiremux.history()| to choose a message.
Recall supplies its final text as one literal Compose input.

If a draft exists, `on_new_payload` controls whether to keep, replace, or
append. You can edit the recalled text or send it to another pane.

History stores confirmed Compose text before delivery. It does not store
direct sends or unconfirmed drafts. Recall does not restore page boundaries
or resolve placeholders again.

Files live in `stdpath("state")/wiremux/history/`.
`index.json` holds metadata.
Each payload has a separate `.txt` file. Picker rows show time, size, and a
preview. Enabled picker previews load only the highlighted payload.

A lower limit removes older entries on the next history access.
A limit of 0 removes all saved entries on that access and disables history.
History access includes recording a confirmed Compose message.

Customize Compose on open ~                       *wiremux-compose-open-event*

Register this handler before you open Compose:
>lua
  vim.api.nvim_create_autocmd("User", {
    pattern = "WiremuxComposeOpen",
    callback = function(event)
      local buf = event.data.buf
      local win = event.data.win
      vim.wo[win].spell = true
      vim.keymap.set("n", "<leader>cs", function()
        require("wiremux").compose.send({ buf = buf })
      end, { buffer = buf, desc = "Send draft" })
    end,
  })
<
The `User` event runs after Wiremux configures the window and installs its
mappings. Data contains `buf`, `win`, and `reopened`.

`reopened` is false for a new window and true for a restored hidden window.
The event does not run when Wiremux only focuses or reconfigures a visible
window. Pass `{ buf = buf }` so an old callback cannot act on another draft.

Placeholder completion ~                              *wiremux-completion*

Optional sources support blink.cmp and nvim-cmp. Type `{` in Compose to see
built-in and custom names. Suggestions do not execute resolvers.

Accepting a suggestion inserts the complete token and replaces an existing
closing brace. Literal pages, including recalled history, disable suggestions.

Keep Wiremux's usual lazy-loading triggers. These examples load its completion
adapter only when you enter Compose.

blink.cmp ~

Merge these fields into your existing blink options:
>lua
  completion = { documentation = { auto_show = true } },
  sources = {
    default = function()
      local sources = { "lsp", "path", "snippets", "buffer" }
      if vim.b.wiremux_compose == true then
        sources[#sources + 1] = "wiremux"
      end
      return sources
    end,
    providers = {
      wiremux = {
        name = "Wiremux",
        module = "wiremux.completion.blink",
        opts = { preview = true },
      },
    },
  },
<
Keep the Compose check in source selection. blink imports a provider before it
checks that provider's `enabled` callback.

For a Markdown source override, use `inherit_defaults = true` or the same
Compose check. Otherwise, the override can bypass the default source list.

nvim-cmp ~

Add `{ name = "wiremux" }` to your sources, including any Markdown override.
After cmp loads, register the source:
>lua
  local function register_wiremux()
    if vim.b.wiremux_compose == true then
      require("wiremux.completion.cmp").register({ preview = true })
    end
  end

  vim.api.nvim_create_autocmd("BufEnter", {
    group = vim.api.nvim_create_augroup("wiremux_cmp", { clear = true }),
    callback = register_wiremux,
  })
  register_wiremux()
<
The immediate call handles an existing Compose window. `BufEnter` handles
later visits. Repeated registration is safe. Both sources use your completion
plugin's mappings.

Preview options ~

`preview = true` shows up to 10 lines and 2048 bytes per value.
For custom limits, use:
>lua
  preview = { max_lines = 15, max_bytes = 4096 }
<
Both limits must be positive integers. Longer values get a truncation notice.
The limits preserve UTF-8 characters and affect only the display.
Sending still resolves the full placeholder value.

Previews use the page's source origin, like `K`. Values can change before you
send. Resolver execution is synchronous. Display limits do not limit the time
spent in Git or custom code.

Completion engines can request resolution for documentation or acceptance.
Omit `preview` or set it to false to show descriptions only.

For automatic documentation, enable blink's
`completion.documentation.auto_show`. With nvim-cmp, keep
`view.docs.auto_open = true`. Use `K` for an explicit full preview.

`b:wiremux_compose` identifies Compose buffers, including hidden drafts.
The sources also check whether the current page permits placeholders.

Dynamic target labels ~

A function label supplies the complete row for an operational managed target.
Wiremux does not add its usual marker, location, or command to that result:
>lua
  label = function(inst, index)
    return string.format(
      "Dev #%d [%s]", index, inst.running_command or "idle"
    )
  end,
<
A string label supplies the target's display name. For a window target, a
non-empty tmux window name takes precedence.
Creation rows use definition names.

The function receives the instance and its index among instances of that name.

Instance fields include `id`, `target`, `kind`, `window_id`,
`window_name`, `window_index`, `pane_index`, `running_command`, `origin`,
`origin_cwd`, and `last_used_at`.

4. CONFIGURATION                                       *wiremux-configuration*

Use one `require("wiremux").setup({ ... })` call. Merge the examples you need
into that options table.

AI target example:
>lua
  require("wiremux").setup({
    targets = {
      definitions = {
        opencode = {
          cmd = "opencode",
          kind = "pane",
          split = "vertical",
          shell = false,
        },
        claudecode = {
          cmd = "claude",
          kind = { "pane", "window" },
          split = "horizontal",
          shell = false,
        },
      },
    },
  })
<
Install the programs you configure. Definitions do not install them.

Top-level options ~

*wiremux-config-log-level*
log_level           string, default "warn"
                    "off", "error", "warn", "info", or "debug".

*wiremux-config-targets*
targets             Table containing definitions.

*wiremux-config-targets-definitions*
targets.definitions Table mapping target names to definitions.

*wiremux-config-context*
context.resolvers   Table mapping placeholder names to functions.
                    See |wiremux-placeholders|.

Target definition fields ~

*wiremux-config-definition-cmd*
cmd                 String or nil. Command to start in the target.

                    If a new definition has no cmd, a send can use its payload
                    as the startup command. Create an empty terminal first
                    before sending arbitrary text to it.

*wiremux-config-definition-kind*
kind                "pane", "window", or a list of those choices.
                    Default: "pane". A list opens a creation choice.

*wiremux-config-definition-split*
split               "horizontal" or "vertical" for panes.
                    Default: "horizontal".

*wiremux-config-definition-split_mode*
split_mode          "before" or "after" for panes. Default: "after".

*wiremux-config-definition-label*
label               String, function, or nil. Display label for managed rows.
                    See Dynamic target labels in |wiremux-howto|.

*wiremux-config-definition-title*
title               String or nil. Name for a new tmux window.
                    Applies only to kind="window". Defaults to a string label
                    or the definition name.

*wiremux-config-definition-shell*
shell               Boolean, default true.
                    true: create a shell, then type cmd.
                    false: run cmd directly through tmux.

*wiremux-config-definition-size*
size                String or nil. Size argument for a new pane.
                    Wiremux passes it to tmux resize-pane.

*wiremux-config-definition-startup-timeout*
startup_timeout     Milliseconds to wait for a new target to render.
                    Default: 3500. Delivery continues after the timeout.

Compose options ~

Set global defaults under `ui.compose`:
  width, height     Screen fractions from 0.1 to 1. Defaults: 0.6 and 0.4.
  title             Default: " Compose Message ".
  border            Border name or segment list. Default: "rounded".
  style             Only "minimal" is supported.
  footer            Show minimal mapping hints. Default: true.
  close_behavior    "ask", "hide", or "discard". Default: "ask".
  on_new_payload    "ask", "keep", "replace", or "append". Default: "ask".
  history_limit     Non-negative integer. Default: 0. Global-only.
  use_default_keymaps  Boolean, default true. Global-only.
  wo                Window options. Defaults: wrap=true, number=false,
                    relativenumber=false.
  keymaps           Action mappings. See |wiremux-compose-keymaps|.

Use session options in a per-send `compose` table. `history_limit` and
`use_default_keymaps` are global-only. See |wiremux-howto-compose|.

Action defaults ~

*wiremux-config-actions*
actions             Action option tables. Support varies by action.
                    Send reads delivery and Compose defaults.
                    Close and focus read their behavior defaults.

                    Toggle reads its focus default and always uses "last".
                    Create does not read actions.create.
                    Creation follows tmux's focus behavior.

                    Effective defaults:
                    send: behavior="pick", focus=true, compose=false.
                    close: behavior="pick".
                    focus: behavior="last".
                    toggle: focus=false.

*wiremux-config-action-behavior*
actions.*.behavior  "pick", "last", or "all".
                    pick chooses a target. last reuses the last target when
                    available. A single matching instance needs no picker.

                    Send and close apply all to every matching managed
                    instance. Focus uses only the first result.
                    Toggle always uses last.

*wiremux-config-action-submit*
actions.send.submit Boolean. Set true to append Enter after the paste.
                    Default: no automatic Enter.

*wiremux-config-action-mode*
actions.send.mode   "auto" (default), "instances", "definitions", or "all".
                    auto prefers matching managed instances. If none match,
                    it offers adoption candidates and definitions.
                    instances limits selection to managed instances.
                    definitions offers creation choices.

                    all can show managed instances, adoption, and creation.

                    For a mixed picker, use mode="all" and behavior="pick".
                    With matching managed instances, behavior="all" sends to
                    all of them. Otherwise, selection can offer adoption or
                    creation. toggle() does not adopt unmanaged panes.

                    Send rows have no marker. `[+]` creates a target.
                    `[adopt]` assigns an unmanaged pane before sending.
                    `[re-adopt]` reassigns a pane whose owner no longer
                    exists.

                    Locations use window_index:pane_index. Cross-session rows
                    include the session ID. Labels can include the tmux window
                    name and current command.

*wiremux-config-action-focus*
actions.*.focus     Boolean. Send and toggle use their focus defaults.
                    Focus always focuses its selected target.
                    Create and close do not read this field.

Picker configuration ~

*wiremux-config-picker*
picker              Table containing adapter, instances, and targets.

*wiremux-config-picker-adapter*
picker.adapter      "fzf-lua", "snacks", a function, or nil.
                    Auto-detection tries fzf-lua, Snacks, then vim.ui.select.
                    An unavailable named adapter also uses auto-detection.

                    A custom function receives (items, opts, on_choice).
                    Wiremux accepts only the first on_choice call.

                    Choose the adapter before the first picker use. Repeating
                    setup() does not reset the cached adapter.

To force vim.ui.select, use a custom adapter:
>lua
  picker = {
    adapter = function(items, opts, on_choice)
      vim.ui.select(items, {
        prompt = opts.prompt,
        format_item = opts.format_item,
      }, on_choice)
    end,
  },
<
File insertion uses an available adapter's file picker. Otherwise, it uses
the built-in file list with the active selection picker.

*wiremux-config-picker-instances*
picker.instances    Instance filter and sort callbacks.

*wiremux-config-picker-instances-filter*
picker.instances.filter
                    Function (inst, state), or nil. See |wiremux-filters|.
                    Defaults to ownership/session filtering,
                    including orphans.

*wiremux-config-picker-instances-sort*
picker.instances.sort
                    Comparator function (a, b), or nil.
                    The default compares last_used_at, newest first.

*wiremux-config-picker-targets*
picker.targets      Definition filter and sort fields.

*wiremux-config-picker-targets-filter*
picker.targets.filter
                    Function (name, definition), or nil.
                    Default: no definition filter.

*wiremux-config-picker-targets-sort*
picker.targets.sort Function or nil. Default: nil.
                    The current implementation does not apply this sort.
                    Definition order is unspecified.

Filter and sort callbacks accept functions, not names such as "recency",
"global", or "name". A nil field in setup retains any shipped default.

4.1 FILTERS                                                *wiremux-filters*

Filters select which instances and definitions can appear in pickers.
Instance filters receive both managed and unmanaged candidates.
An unmanaged instance can have `target = nil`.

Instance fields include:
  id, managed, orphaned, target, origin, origin_cwd, kind, session_id,
  window_id, window_name, window_index, pane_index, running_command,
  last_used_at.

State fields include:
  origin_pane_id, session_id, last_used_target_id, instances.

The shipped instance filter is:
>lua
  filter = function(inst, state)
    if not inst.managed or inst.orphaned then
      return inst.session_id == state.session_id
    end
    return inst.origin == state.origin_pane_id
  end
<
Managed targets belong to their source Neovim pane by default.
Same-session unmanaged panes and proven orphans can appear for adoption.
Wiremux always excludes the current pane.

An orphan is a managed target whose recorded owner no longer exists in a
complete tmux snapshot. Re-adoption preserves its name and kind.
Foreign targets with live owners are not orphans.

Only targets owned by this Neovim pane:
>lua
  picker = {
    instances = {
      filter = function(inst, state)
        return inst.managed and inst.origin == state.origin_pane_id
      end,
    },
  },
<
Targets created from this directory:
>lua
  picker = {
    instances = {
      filter = function(inst)
        return inst.managed and inst.origin_cwd == vim.fn.getcwd()
      end,
    },
  },
<
All queried candidates:
>lua
  picker = {
    instances = {
      filter = function() return true end,
    },
  },
<
The last example can include other sessions. It still excludes the current
pane. A nil filter in setup does not disable the shipped filter.

Per-call filters override the corresponding picker filter:
>lua
  require("wiremux").send("text", {
    filter = {
      instances = function(inst, state)
        return inst.session_id == state.session_id
      end,
      definitions = function(name, definition)
        return name == "opencode"
      end,
    },
  })
<
`filter.instances` receives (inst, state).
`filter.definitions` receives (name, definition).

For a custom instance order, provide a comparator:
>lua
  picker = {
    instances = {
      sort = function(a, b)
        return (a.last_used_at or 0) > (b.last_used_at or 0)
      end,
    },
  },
<
Adoption candidates keep backend query order after managed instance rows.

5. PLACEHOLDERS                                        *wiremux-placeholders*

A placeholder is a name inside braces, such as `{file}`.
Names match `[A-Za-z_][A-Za-z0-9_]*`.

Built-in values:
  {file}             Source file path, not contents.
  {filename}         File name without its directory.
  {position}         Source location as file:line:col, with one-based numbers.
  {line}             Source line text.
  {selection}        Visual selection, or an empty string.
  {this}             Source location and any visual selection.
  {diagnostics}      Diagnostics on the source line.
  {diagnostics_all}  All diagnostics in the source buffer.
  {quickfix}         Current quickfix entries.
  {buffers}          Names of listed, loaded buffers.
  {changes}          Git changes for the source file against HEAD.

Wiremux captures the source location, selection, and line when
`send()` begins.
It captures them before a prompt picker opens. Each Compose page retains its
own source origin.

Direct sends resolve text after prompt selection and before target selection.
Compose resolves each page when you confirm the draft, also before target
selection. Cancelling a target picker does not prevent that earlier work.

Within one text-resolution call, each distinct name resolves once.
Compose resolves pages separately. Preview and availability checks can run
resolvers again.

A non-empty string replaces the token. An empty string removes it.
Unknown names, nil, resolver errors, and non-string results leave it literal.
There is no automatic retry after delivery.

Set `placeholders = false` on a send item to keep tokens literal, including
names typed into its draft later. History and motion sends use this behavior.

The source file path, selection, and source line stay fixed for a page.
Diagnostics, Git changes, buffers, and quickfix values resolve later.
Unavailable diagnostics remain literal if no source buffer can be found.

Custom resolvers ~

Add functions under `context.resolvers`:
>lua
  context = {
    resolvers = {
      git_branch = function()
        local result = vim.system(
          { "git", "branch", "--show-current" }, { text = true }
        ):wait()
        return result.code == 0 and vim.trim(result.stdout) or nil
      end,
      source_path = function(origin)
        return origin and origin.path or vim.api.nvim_buf_get_name(0)
      end,
    },
  },
<
Resolver names use the same grammar as placeholder names.
A new setup replaces custom resolvers and retains built-in resolvers.

A resolver receives a copy of the source origin:
  bufnr       Source buffer number.
  path        Source path.
  row         One-based line number.
  col         Zero-based byte column.
  selection   Selected text.
  line        Source line text.

Read these fields for values tied to the source location.
A resolver without arguments can still read current editor state at resolution
time. Use literal page text for custom values that must stay fixed.

Keep resolvers fast. Do not change editor state from a resolver.

Check availability ~

`context.is_available(name)` runs the resolver and checks for a non-empty
string. Use it in a send item's visibility function:
>lua
  {
    label = "Test selection",
    value = "jest -t '{selection}'",
    visible = function()
      return require("wiremux.context").is_available("selection")
    end,
  }
<
Availability checks use current editor state, not a saved Compose origin.
A visibility callback can therefore execute resolvers before prompt selection.

7. LUA API                                                 *wiremux-api*

Use `require("wiremux")` for root actions.

                                                   *wiremux.setup()*
wiremux.setup({opts})
        Configure Wiremux. Each call starts from shipped defaults.

                                                    *wiremux.send()*
wiremux.send({text|items}, {opts})
        Send a string, one item, or a list of items.
        Without text, open or resume Compose.

        Call options include behavior, mode, target, filter, focus, submit,
        pre_keys, post_keys, and compose. Action defaults fill omitted values.

        target is a definition-name string. After filters, it selects
        matching managed instances or offers that definition for creation.
        Explicit targeting takes precedence over mode and does not adopt.

        Invalid delivery options abort before any picker opens.
        Invalid item fields or selected Compose options skip that item with
        warnings. Valid items remain available.
        See |wiremux-howto-compose| for Compose precedence.

Send item fields ~

Each item needs `value`. Other fields are optional:
  value          String. Raw text or command.
  label          String. Name in the prompt picker. Defaults to value.
  title          String. Name for a newly created tmux window.
  submit         Boolean. Append Enter after the text.
  compose        Boolean or session options table.
  placeholders   Boolean. Set false to preserve literal tokens.
  visible        Boolean or zero-argument function returning a boolean.
  pre_keys       String or list of tmux key names before the paste.
  post_keys      String or list of tmux key names after the paste.

Item submit, pre_keys, and post_keys override call options.
Item compose follows the precedence in |wiremux-howto-compose|.

Commands with Enter:
>lua
  require("wiremux").send({
    { label = "Run tests", value = "npm test", submit = true },
    { label = "Run dev", value = "npm run dev", submit = true },
  })
<
Conditional visibility:
>lua
  require("wiremux").send({
    {
      label = "TypeScript check",
      value = "npx tsc --noEmit",
      submit = true,
      visible = function() return vim.bo.filetype == "typescript" end,
    },
  })
<
Both examples send commands. Use a shell target that is ready to receive them.

                                                 *wiremux.history()*
wiremux.history()
        Open the same picker as |:Wiremux-history|.
        Selection opens saved text in Compose without sending it.
        History is opt-in. See |wiremux-compose-history|.

                                                   *wiremux.focus()*
wiremux.focus({opts})
        Focus a target. Options: behavior, target, and filter.
        If no instance matches, an explicit target can offer creation.

                                                  *wiremux.create()*
wiremux.create({opts})
        Create a target from definitions. Options: target and filter.
        With target, an existing filtered instance prevents another creation.

                                                   *wiremux.close()*
wiremux.close({opts})
        Close a tmux target, not a draft.
        Options: behavior, target, and filter. See |wiremux.compose.close()|.

                                                   *wiremux.adopt()*
wiremux.adopt({opts})
        Assign an existing pane to the current Neovim pane without sending.
        The default picker includes same-session panes. It excludes the
        current pane and shows existing ownership.

        `opts.filter.instances(inst, state)` replaces that default filter.
        It can include other sessions. `opts.format_item` replaces row text.

        An unnamed pane gets a generated name such as pane-3.
        `opts.target` supplies a name for an unassigned pane. Existing target
        names and kinds are preserved during re-adoption.

Example: adopt a shell as terminal:
>lua
  require("wiremux").adopt({
    target = "terminal",
    filter = {
      instances = function(inst)
        return inst.running_command == "zsh"
      end,
    },
  })
<
Example: include other sessions and customize rows:
>lua
  require("wiremux").adopt({
    filter = { instances = function() return true end },
    format_item = function(pane)
      return string.format(
        "%s %s %s", pane.target or "unmanaged", pane.id,
        pane.running_command or ""
      )
    end,
  })
<
                                                  *wiremux.toggle()*
wiremux.toggle({opts})
        Toggle pane visibility through tmux zoom, or switch windows.
        Options: mode, target, filter, and focus.
        With no matching instance, offer creation from definitions.

        Current limitations: toggle can use an unfiltered last-used instance
        instead of the selected target. If actions.toggle.focus is true,
        a per-call focus=false does not disable focus.

                                             *wiremux.send_motion()*
wiremux.send_motion({opts})
        Set operatorfunc and return "g@". Forward options to send().
        Use an expression mapping. See |wiremux-howto-send-motion|.

Compose actions ~                                    *wiremux-compose-api*

Use `require("wiremux").compose` or `require("wiremux.compose")`.
Both expose the same handlers as the Compose mappings.

Each method accepts an optional table with one field:
  buf   Non-negative integer. Omitted or 0 means the current buffer.

A valid action focuses the Compose window and checks the session again after
autocmds run. It never opens a missing draft or acts on a tmux target.

Return values:
  accepted   Boolean. True means the handler accepted the action.
             It does not prove successful sending or delivery.
  reason     String or nil. A rejected action returns false and one reason:
             no_session: no active draft.
             stale_buffer: buffer or focus no longer matches.
             hidden: the draft is hidden.
             busy: the session is not editing.

Invalid arguments raise an error. Rejected actions do not invoke a handler or
fall back to another draft. Pass `buf` in native callbacks to prevent stale
callbacks from acting on a newer draft.

                                              *wiremux.compose.send()*
wiremux.compose.send({opts})
        Confirm all pages through the send handler.
        Acceptance does not prove delivery.

                                             *wiremux.compose.close()*
wiremux.compose.close({opts})
        Close according to close_behavior: ask, hide, or discard.
        Root |wiremux.close()| closes a tmux target instead.

                                       *wiremux.compose.append_next()*
wiremux.compose.append_next({opts})
        Hide the draft and append the next non-empty Compose input once.
        This bypasses on_new_payload. It does not send or record history.

                                           *wiremux.compose.discard()*
wiremux.compose.discard({opts})
        Discard the current page. With one page, discard the draft and close
        without asking. Otherwise, keep the remaining pages open.

                                             *wiremux.compose.files()*
wiremux.compose.files({opts})
        Choose a file and insert its path at the Compose cursor.

                                       *wiremux.compose.delete_page()*
wiremux.compose.delete_page({opts})
        Delete the page and select the next, wrapping to the first.
        With one page, clear its text and keep Compose open.

                               *wiremux.compose.preview_placeholder()*
wiremux.compose.preview_placeholder({opts})
        Preview the placeholder under the cursor. Invoke again to enter the
        preview. This does not change the page.

                                          *wiremux.compose.previous()*
wiremux.compose.previous({opts})
        Select the previous page.

                                              *wiremux.compose.next()*
wiremux.compose.next({opts})
        Select the next page.

8. STATUSLINE                                           *wiremux-statusline*

                                                   *wiremux.statusline*
Use `require("wiremux").statusline` for statusline integration.

                                     *wiremux.statusline.component()*
wiremux.statusline.component()
        Return a provider function. The first call schedules a refresh and
        registers FocusGained updates. The provider displays a count and the
        last-used target name when targets are available.

                                       *wiremux.statusline.get_info()*
wiremux.statusline.get_info()
        Return cached { loading, count, last_used } without starting a fetch.
        Call component() once to enable initial and FocusGained refreshes.

        last_used is nil or a table with id, target, kind, and name.
        The instance filter also applies to the statusline count.

Usage ~                                         *wiremux-statusline-usage*

Lualine:
>lua
  {
    require("wiremux").statusline.component(),
    padding = { left = 1, right = 1 },
  }
<
For heirline or feline, use the returned function as a provider.

Custom display:
>lua
  local statusline = require("wiremux").statusline
  statusline.component()
  local function wiremux_status()
    local info = statusline.get_info()
    if info.loading or info.count == 0 then
      return ""
    end
    return string.format("[tmux:%d]", info.count)
  end
<
Use `wiremux_status` as your statusline provider.

Refresh behavior ~                              *wiremux-statusline-design*

Wiremux operations update the cache from their state snapshots.
`component()` also requests asynchronous updates initially and on FocusGained.
There is no periodic timer or debounce in the current statusline module.

                                       *wiremux.statusline.refresh()*
`statusline.refresh()` is not a public function. Use `component()` to enable
the supported automatic refresh behavior.

9. TROUBLESHOOTING                                 *wiremux-troubleshooting*

Run `:checkhealth wiremux` or `:Wiremux health` first.

No targets or no backend:
  - Make sure that Neovim runs inside tmux and that `$TMUX` is set.
  - Check target definitions and installed commands.
  - Check instance and definition filters.

Picker problems:
  - Use auto-detection or the custom vim.ui.select adapter example.
  - Choose an adapter before the first picker opens.

Missing placeholders:
  - Check the name and resolver. Unknown or unavailable values stay literal.
  - Select code before invoking a selection-based mapping.
  - Use `K` in Compose to inspect a value without sending it.

Missing history:
  - Set ui.compose.history_limit to a positive integer before history access.
  - History stores only confirmed Compose messages.
  - Unsent drafts do not survive a Neovim restart.

10. DESIGN NOTES                                         *wiremux-explanation*

Target metadata lives in tmux pane options such as `@wiremux_target`.
It survives Neovim restarts. Ownership filters control which targets each
editor sees. History is separate local state. See |wiremux-compose-history|.

Send sequence ~

1. Capture the source origin and validate options.
2. If the call supplies a list, choose a prompt.
3. Resolve direct text, or resolve Compose pages after confirmation.
4. Select, adopt, or create the target.
5. Deliver the prepared payload.

Compose trims trailing whitespace from each page and joins pages with one
blank line. Backends receive the final text, not the Compose page model.

Tmux delivery replaces tabs with two spaces and removes one final newline.
Literal placeholder handling does not preserve text byte for byte.

Table ownership ~

`setup()` owns a copy of its option tree. Compose owns its session
configuration. Consumers treat prepared requests as read-only.

`send()` reads the supplied filter, key, and Compose option tables.
While a send is pending, do not modify these tables.
